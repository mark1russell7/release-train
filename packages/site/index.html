    How the train works

    The release train reads the npm packages of the GitHub account mark1russell7. It makes the dependency graph of these packages and a plan of the next releases and updates. The train does not publish to npm itself. The release workflow of each repository publishes.

    1

    Plan

    The train reads each repository, each lockfile and npm. It gives the actions in waves. This stage changes nothing.

    2

    Apply

    The train opens one pull request for each repository of the current wave, with the new ranges and the new lockfile.

    3

    Template sync

    The train keeps the files from the template current in each repository, in a second pull request.

    The actions of the plan

    ActionWhen
    New packageThe package is not on npm. Only the owner can make a new package.
    ReleaseThe version on main is newer than npm, or a dependency range of the package changes.
    Update lockfileThe range lets the newest version in, but the lockfile holds an older version. A lockfile update is sufficient.
    Change rangesThe newest version is outside the range. The range changes to a caret range of the new version.

    Each repository gets one combined action of each kind. The plan puts the actions in a topological sequence and shows each cycle.

    The new version of a dependent

    • A new version outside the range of a dependent changes that range. The dependent then needs a release too, else its users do not get the change.
    • A change of a peer range breaks the API. This gives MAJOR, or MINOR before 1.0.0.
    • For a change of a runtime range, apply reads the public types of the dependent. When the types name the changed package, the release breaks the API. Else it is a patch.

    Blocks and holds

    • A github:, git, file: or link: specifier in a runtime section of a published package blocks its release. npm users cannot install it.
    • The train moves a repository only to a version that the release.yml of its own repository built. npm gives this provenance. A version with no provenance waits for a person.
    • A release waits for the range changes of its repository, and for each runtime dependency on npm.

    Use

    GH_TOKEN=$(gh auth token) pnpm --filter @release-train/release-train plan
node packages/release-train/src/bin.ts plan --json
node packages/release-train/src/bin.ts plan --write-db <folder>
GH_TOKEN=<token> node packages/release-train/src/bin.ts apply --dry-run
    • --public-only removes each private repository from the output.
    • --out <file> writes the full plan as JSON.
    • --dry-run shows the pull requests of apply and changes nothing.
    • --only <repo> changes only the given repositories.

    CI

    • plan.yml computes the plan every 6 hours with the default token, so it sees only public repositories.
    • train.yml starts every 30 minutes and on each new release. It uses the token of a GitHub App, so its pull requests start CI.
    • The log and the artifacts of a run give each private repository only as a count or a hash.
